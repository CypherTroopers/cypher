Common RPC Miner Transaction Admission

This branch introduces a Common RPC Miner transaction admission flow.

In the previous test setup, common miners were mainly responsible for mining.
With this update, common miners also receive transactions through RPC, sign a transaction admission record, and earn a portion of the transaction fee when the transaction is included in a block.

The validator leader and validator committee remain responsible for block production and finality.
Common miners do not replace validator consensus. Instead, they provide the public RPC transaction entry point and submit signed admission records for the transactions they accepted.

Design Overview

User / Wallet
  ↓
Common Miner RPC
  ↓
Signed CommonTxAdmission
  ↓
Relay to validator leader
  ↓
Validator leader includes tx + admission in tx block body
  ↓
Validator committee finalizes block
  ↓
Common miner receives 20% of actual tx fee
  ↓
Remaining 80% is burned

Validator and Common Miner Roles

Validator leader / fixed validator committee

The validator leader and fixed validator committee are responsible for:

* Creating transaction blocks
* Running validator HotStuff consensus
* Finalizing blocks
* Verifying CommonTxAdmission
* Verifying CommonTxReward
* Applying the common RPC reward and burn rule during state processing

Validator RPC can be closed to the public network.
Validators can focus on consensus, verification, and block production.

Common miners

Common miners are responsible for:

* Opening public RPC endpoints
* Receiving user transactions
* Recording transaction admission
* Signing CommonTxAdmission using ECDSA
* Relaying signed admission records to validator/leader nodes
* Receiving 20% of the actual transaction fee when the admitted transaction is included in a block

This allows common miners to compete by operating reliable public RPC endpoints.
If more common miners join, more public RPC endpoints can become available.

⸻

CommonTxAdmission

CommonTxAdmission records which common miner accepted a transaction.

The admission data includes:

chainId
txHash
miner
keyBlockNumber
txBlockNumber
timestamp
signature

The signature is generated by the common miner using ECDSA.

The validator verifies:

1. txHash is not empty
2. miner address is not empty
3. chainId matches the current chain config
4. ECDSA signature can be recovered
5. recovered address matches admission.miner
6. duplicate admissions for the same tx are rejected

Chain ID Replay Protection

chainId is included in the signed admission payload.

This prevents a signed CommonTxAdmission from being reused on another Cypherium chain or testnet.

The admission signature covers:

domain
chainId
txHash
miner
keyBlockNumber
txBlockNumber
timestamp

If the CommonTxAdmission.chainId does not match the current ChainConfig.ChainID, the block is rejected during state processing.

⸻

Block Body Additions

Transaction blocks can include:

CommonTxAdmissions
CommonTxRewards

The block header includes:

commonTxAdmissionRoot
commonTxRewardRoot

These roots are derived from the common admission and reward records included in the block body.

During block processing, the validator checks that:

DeriveCommonTxAdmissionRoot(block.CommonTxAdmissions()) == header.CommonTxAdmissionRoot
DeriveCommonTxRewardRoot(block.CommonTxRewards()) == header.CommonTxRewardRoot

If the roots do not match, the block is invalid.

⸻

Common RPC Reward Rule

When a transaction admitted by a common miner is included in a block, the actual transaction fee is split as follows:

20% → common RPC miner reward
80% → burned

The actual transaction fee is calculated from the real execution result:

actualTxFee = gasUsed × effectiveGasPrice
commonRpcReward = actualTxFee / 5
commonRpcBurn = actualTxFee - commonRpcReward

The validator verifies the reward values during state processing.

If the included CommonTxReward does not match the actual gas used and effective gas price, the block is rejected.

Example Fee Calculation

For a normal transfer:

gasUsed = 21000
effectiveGasPrice = 1,000,000,000 wei

Total transaction fee:

21000 × 1,000,000,000
= 21,000,000,000,000 wei
= 0.000021 CPH

Common miner reward:

20% = 4,200,000,000,000 wei
    = 0.0000042 CPH

Burn:

80% = 16,800,000,000,000 wei
    = 0.0000168 CPH

Example hex values:

commonRpcReward = 0x3d1e3821000
commonRpcBurn   = 0xf478e084000

Notes

This feature does not make common miners validator consensus members.

Common miners only provide transaction admission through RPC and receive a fee share when their admitted transaction is included in a finalized block.

Validator nodes still verify all admission records, reward records, roots, signatures, and chain ID before accepting the block.
