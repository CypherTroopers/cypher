# Financial state v6 / collector generation v2

Q3 implementation specification, 2026-09-23. This is a new explicitly selected
devnet generation: authenticated CLX DEX config v4, execution schema 5, rolling
CLX evidence and financial state v6. Previous v1–v5 fixtures retain their codec
and arithmetic. This document does not claim LIVE testing.

Financial v6 adds `FeeHistory` after the existing JSON fields; `Fees` is an empty
array. Canonical field order within FeeHistory is Version, ClosedPeriod,
ClosedTotal, ClosedRoot, Open, LastFee. Version is 1. Open entries are ordered
`{Period, Total}`; periods are absolute ten-block reward periods. Only nonzero
totals are stored, at most 16 unclosed periods. Missing periods mean zero fees,
not missing evidence. LastFee binds the current FinanceSummary.CollectedFees.
Open totals sum exactly to engine.PeriodFees. ClosedPeriod equals the engine's
sequential RewardPeriod. ClosedTotal is the uint128 sum of fees from closed
periods, not the amount paid as rewards. ClosedRoot starts at zero and advances
with `Digest("common-dex/closed-fee-period/v1", previousRoot || uint64BE(period)
|| uint256BE(periodFees))`. Financial state root uses
`common-dex/financial-state/v6`. Existing reward formula, support limits, FIFO,
cash/PnL, funding, dust, reservations, and claim encoding remain unchanged.

Reward close reads its exact period total and removes only that period after
authenticated committed-participation verification. Archived finalized states
and checkpoints preserve the detailed historical basis. The active state
retains the closed accumulator and all unpaid reservations. When 16 different
unclosed periods already contain fees, an action creating fees in a seventeenth
period is rejected atomically. Zero-fee work continues; absent reward evidence
does not force an unconditional market halt. This is explicit backlog pressure,
not an assertion of unrestricted liveness under permanent evidence withholding.

`Execution.ValidateSnapshot(raw,height,root)` checks canonical decoding,
financial/engine invariants, absolute height and state-root equality. Consensus
must separately verify the checkpoint, descendant finality, genesis connection,
and own voting safety. A checksum or this function alone is not authentication.

Continuous participation uses all positive heights of the fixed authenticated
epoch, rather than a finite ReceiptHeights fixture. Signature-time rules and the
pre-vote ClosedThrough watermark remain unchanged. Runtime proof collection is
still local: consensus validity only reads committed parent participation.

Collector retirement requires a verified finalized checkpoint whose RewardPeriod
is the next sequential period; no height-only or local-close authority exists.
Before hot deletion, an immutable archive stores the finalized checkpoint and
descendant proof, previous archive commitment, and all retired target/receipt/
certificate/local-close records, including locally known evidence omitted from
the committed close. The archive is fsynced and its directory is fsynced before
the active WAL publishes its retired period/hash. LastVote, its target, the
immediately previous RecoveryVote/target, ClosedThrough, and all unclosed
evidence remain hot. BeforeVote's collector fsync precedes the FHS WAL fsync;
the previous pin permits restart if that second write failed. FHS persistence
failure disables further signing, so no second unacknowledged advance occurs.
Old records cannot issue
new signatures after retirement. A crash before active publication retries the
identical archive; after publication recovery requires that archive, with no
fallback to an older watermark. Existing local collector formats are explicitly
distinguished by the new optional retired frontier; no old bytes acquire a new
meaning.

The collector WAL remains limited to 2048 records / 2 MiB; retirement archives
are limited to 1024 periods / 128 MiB total, each at most 2 MiB. Archives are not
deleted to manufacture capacity. Exhaustion stops retirement/receipt work with
an explicit error and preserves all safety and claim evidence. Replication's
in-memory receipt/certificate caches discard only periods covered by the
durable retired frontier; old network replays are rejected. Hot-map pruning is
independent of TLS delivery acknowledgement and of CLX claim payment.

Independent vectors are generated by `scripts/dex/financial_storage_reference.py`
and checked by Go tests. UNIT and LIVE outcomes are recorded separately.

### Repeated collector/FHS WAL crash boundary (2026-09-23 correction)

`BeforeVote` fsyncs the collector before the independent FHS safety WAL. A
collector-only attempted vote is therefore not evidence that the FHS WAL has
advanced. On startup, `CheckFHSWatermark` authenticates and pins the actual FHS
watermark for the first successful pre-signature callback. That callback saves
the actual restored vote as `RecoveryVote`, even after repeated crashes at the
same two-WAL boundary. Subsequent callbacks may advance the pin to the previous
collector vote because an FHS persistence failure halts the application. Exact
retry of the collector tip also consumes this startup marker: if another callback
occurs, the exact retry has reached the FHS WAL. The next collector save preserves
that vote. This is a trusted pre-signature interface, not a caller-provided height.

`TestCollectorRetiredPinSurvivesRepeatedCollectorAheadCrashes` reproduced the
original failure before the correction. `TestCollectorExactRetryAdvancesRecoveredFHSPin`
covers exact retry followed by another pre-FHS-fsync crash. The change does not
permit old or conflicting votes or delete archived participation evidence.

A second reviewed boundary concerns an archive hard link which reached disk before
its active frontier update. `OpenCollector` now completes this single pending tail
before any actor/network certificate admission: the canonical `state.json` must
exist, filename period and previous hash must match, the registered committee's
full descendant proof must verify, and the archive must equal the old hot set
reconstructed by `RetireFinalized`. Only then is the frontier published and stale
staging reclaimed. A corrupt/foreign archive or missing active WAL is rejected;
there is no archive-as-fresh-root fallback. Previously acknowledged evidence remains
in the authenticated archive, while newly delivered certificates for the already
finalized/retired period are explicitly rejected before acceptance. Tests preserve
the original failing delayed-certificate trace and cover lost active WAL and an
old valid proof copied to the next period's filename.
