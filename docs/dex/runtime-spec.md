# DEX optional runtime boundary v0 (isolated devnet only)

This specification precedes its Go implementation. It is a lifecycle boundary and bounded worker, not an FHS implementation or proof that real CLX/PoW/RPC processes are integrated.

1. Zero configuration is disabled. Constructing a disabled runtime calls no executor factory and allocates no job queue or WAL. It cannot acquire voting rights. Enabled construction validates an immutable copy of chain/genesis/DEX identity, nonzero epoch, committee commitment, vote-key fingerprint, reward recipient, and explicit queue byte/item limits. `Identity.VoteKey[32]` is a registered fingerprint, not a raw 64-byte BLS public key; its mapping to the authenticated key is the registry adapter's responsibility.
2. States are `disabled -> configured -> syncing -> eligible -> active -> leaving -> inactive`. Disabled requires a new enabled configuration to start. A failed active worker becomes inactive and requires fresh construction and synchronization. No automatic eligibility, automatic restart, or role substitution is allowed.
3. `BeginSync` opens only the DEX executor using its factory. The factory is the ownership boundary for a future dedicated WAL and data store. `CompleteSync` calls two separate trusted adapters: registration verification and snapshot verification. Registration must match chain/genesis/DEX/epoch/committee/vote-key fingerprint/reward recipient exactly and its activation height must be at or below the authenticated CLX height supplied to the verifier. The snapshot verifier must authenticate root/height against finalized DEX state and validate actually retrieved data; the `DataAvailable` Boolean is only an early failure signal and cannot authorize participation. Enabled construction rejects either missing adapter. Production registry and snapshot authentication adapters are not implemented by this runtime.
4. `Start` accepts only eligible runtimes. It starts one worker with a bounded item/byte queue. Admission copies request bytes, returns a buffered completion handle, and never waits for execution. Item or byte saturation returns `ErrQueueFull`. Each payload also has a maximum size. Ingress acceptance is not DEX finality or CLX settlement.
5. `Stop` cancels the worker and rejects new work immediately, then waits subject to the caller's context. Queued requests complete with `ErrInactive`. An executor which ignores cancellation leaves the runtime in leaving; no other role is stopped to recover resources. Executors must implement cancellation. Panic is contained to this worker, recorded as a local failure, and never considered a certified state transition.
6. The coordinator dispatches Start/Stop to a named independent PoW, RPC, or DEX role. It holds no coordinator lock while executing a role callback. Failure in one role does not invoke another role's Stop. This is a sidecar boundary candidate and deliberately is not wired to `miner.start/stop`, CLX committee globals, or Common RPC registry setters.
7. Runtime config fields are values (fixed arrays and integers); Config returns a copy. DEX reward changes require a new registered config. The runtime never possesses a reward spending key, writes a CLX coinbase, or modifies an RPC recipient.

Error behavior is fail closed: disabled/unready/invalid transition, unmatched registration, unavailable data, rejected verifier, oversized job, full queue, inactive worker, and executor failure remain distinguishable. No local time is used for financial state or voting eligibility.

Tests use seven deterministic registered identities only as devnet fixture metadata. No PoW, deposit, bond, support allocation, public Sybil policy, or production fees are prerequisites or defaults. All eight PoW/RPC/DEX choices will be exercised with live workers. These tests establish the coordinator/runtime boundary, not acceptance R01/R04 for a real CLX distributed network. Crash containment here is a recovered Go panic; OS process isolation remains a separate test.

## Recorded validation

On 2026-09-21, `GOCACHE=/tmp/common-dex-devnet.0wvjd5/gocache GOPROXY=off go test -race ./dex/runtime -count=1 -json` passed. Raw output: `docs/dex/results/runtime-race.jsonl`. The eight configurations execute actual goroutines and acknowledge work; other roles still acknowledge work after a DEX queue fills, a worker panics, or a stop times out. Tests also cover disabled factory/queue absence, seven registration fixtures, unknown/future/zero epochs, unavailable data, missing snapshot verifier, caller-asserted availability with unauthenticated root/height, immutable identity copies, late factory cleanup, request copying, per-request and aggregate queue byte limits.

Actual ColossusX mining, existing Common RPC endpoints, CLX committee advancement, seven OS processes, FHS WAL/vote replay, cryptographic registry authentication, CPU/RAM resource limits, native CLX operations, and performance comparisons are NOT_RUN by this package. An executor Close error or panic is retained in Stats.LastError; Stop indicates worker shutdown completion rather than proving storage durability. No claim of A–D completion follows from these runtime tests.
