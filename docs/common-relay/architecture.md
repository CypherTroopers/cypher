# Fixed FHS-D common-node relay

This change targets a **fresh FHS-D genesis**. It adds `cphrelay/1`, a negotiated request/response protocol on existing RLPx connections. It retains QUIC between explicitly enabled gateways and canonical committee ingress. It does not enable naked transaction gossip, split admission certificates, reduce receipt quorum, or add libp2p.

## Why common nodes previously needed committee connectivity

`eth/handler.go` rejects naked FHS transaction propagation; admission-only gossip is not a substitute for a paired authenticated packet. `eth/tx_quic_ingress.go` owns the durable origin outbox and previously sent each placement directly to canonical committee QUIC endpoints. Each transaction item still needs `2f+1 = n-f` distinct committee durable receipts, with durable tail delivery continuing to the remaining members. `miner/worker.go:wait` previously invoked the direct all-member PoW transport. Ordinary block/keyblock synchronization over eth/RLPx is separate from these submission paths.

`eth/common_node_peer_policy.go` and `eth/discovery.go` do not authenticate committee membership. Common-role discovery suppression is lifted when relay mode is enabled, allowing public common nodes to discover each other. Committee consensus still uses the existing authenticated rnet/BLS path. An IP address, advertised coinbase, or enode reservation is not BLS consensus membership.

## Request and receipt boundary

`p2p/relay/relay.go` implements `Relay.Protocol`, `Do`, `runPeer`, `routeLocked`, `advanceLocked`, `finishLocked`, and fixed validation/egress worker pools. Requests contain chain/genesis identity, generation, key height, a canonical committee BLS target, an immutable payload, semantic request ID, expiry, and decreasing TTL. They contain **no caller-selected endpoint**. Relays resolve the target through their own canonical route at validation and again immediately before gateway egress.

`eth/common_relay.go` wires transaction dispatch through `TxQUICIngress.dispatchReceipt`, `Ethereum.forwardRelayTx`, `validateRelayRequest`, `validateRelayReply`, and `relayGateway`. All outbox placement, initial quorum, and background/tail receipt sends use the dispatch hook. Gateways reuse `forwardPayloadReceiptContext` and its bounded canonical per-endpoint client pool. They forward the original authenticated packet and return the original BLS-signed ACK fields. The origin validates the original expected committee key, chain/genesis, generation, batch ID, sender/epoch/nonce, item count, and outcome bitmaps before the unchanged per-item quorum accumulator sees a receipt. A relay queue admission or failure response grants no ownership.

The admission certificate's `Miner` and `RewardRecipient` remain unchanged, even when the transport packet sender is a different authenticated RPC operator. Relays never publish transactions or create replacement certificates. Existing origin WAL/outbox retry and crash recovery remain the reliability owner. A disconnected/unreachable route fails closed; enabled common nodes never silently open direct committee ingress connections.

`miner/worker.go:wait` now uses the miner backend's `BroadcastPoWResult`; `eth/common_relay.go` selects the overlay when enabled. `core/pow_result_receipt.go:BroadcastPoWResultVia` retains all-member delivery/retry semantics. Only the gateway calls `ForwardPoWResultReceipt`. `core/pow_result_udp.go` preserves the original result and verifies admission before replying. PoW transport v2 adds a portable BLS receipt over the whole original result digest, parent generation, signer, status, error code and reason. The origin verifies that receipt and its outcome. This authenticates committee admission, **not durable disk ownership, inclusion, or finality**.

`core/types/candidate.go:SealHash` encodes a pointer to Candidate and propagates RLP errors. Previously, the pointer-receiver codec was skipped when hashing a value and the error was discarded, potentially producing Keccak(empty). `consensus/colossusX/consensus.go:VerifyCandidate` and `sealer.go:SealCandidate` use the checked path. The seal binds the work header, miner public identity, reward recipient, IP and port. Compact reconstruction restores chain-computed difficulty; currently mined compact work has zero CommitteeHash. Certified/live/recovery sidecars must continue carrying the original work fields rather than substituting the later carrier keyblock's transaction height/committee hash.

The genesis commitment domain is now `cypher-fhs-genesis-config-v4-bound-pow`. The shipped `genesis.json` changes **only** mixHash, to `0xe4626eb7946b1d869ffd3fcd3136652fcae7ea1f912f8b7101a2e98a266050df`. Existing v3 data is incompatible. No database migration/reset has been executed.

## Bounds and failover

Defaults: 64 relay peers, 128 pending requests, 128 MiB each for pending payload accounting, validation jobs, and retained gateway egress; 16 outstanding requests/16 MiB per upstream peer; 16 frames/8 MiB per peer output queue; four validation workers and eight gateway workers; fanout two; TTL three (examples use four); 15-second expiry; 64 messages/sec and 8 MiB/sec per peer with one maximum-frame byte burst; 128 cache entries/4 MiB. Configuration has strict maxima. TTL is counted including the gateway: origin→common→gateway needs three. Responses are also rate/byte charged.

A pending request has at most Fanout active children. Negative responses/disconnects advance immediately to untried neighbors. A timer retires a silent wave and advances, bounded by the original expiry. The bounded neighbor list is exhausted within the usable timeout when possible; each retry changes the initial ordering through a scalar salt, preventing the same semantic PoW request from permanently choosing the same failed subset. Very short deadlines and high degree may require multiple origin retries. Expired child responses are unmatched and cannot spoof success. Duplicate concurrent paths share pending state and one gateway egress; verified receipts have a bounded cache. Duplicate parents consume their own outstanding quotas. One peer cannot fill all pending slots at default quotas. Source waiters, validation jobs, and output buffers have independent bounds.

Gateway egress bytes remain charged while a canceled request is still retained by a queue or executing hook. `Stop` cancels workers, pending work and connections, joins protocol readers/writers and fixed worker pools, and drains retained jobs. No goroutine is created per untrusted relay packet. PoW expensive candidate verification is serialized with retryable busy/full responses and a 4096-entry admission cap; transport workers and replay tables retain their existing limits. TxQUIC also charges an authenticated origin bucket in its existing bounded rate table, in addition to the transport IP bucket. Gateways share an IP bucket at committee ingress, so operators must size that existing budget for their actual expected load.

**These bounds are not a total RSS limit.** Pending, validation, egress and output accounting are separate budgets. A conservative sum includes up to three times MaxPendingBytes, MaxPeers times PeerQueueBytes, cache bytes, active decoding/encoding copies and application storage. More significantly, unchanged `p2p/rlpx.go:rlpxFrameRW.ReadMsg` accepts frames up to **257 MiB** and allocates the padded frame before subprotocol dispatch. With snappy enabled it may also allocate a compressed-payload copy and up to 257 MiB decoded output. The relay's 4 MiB packet cap applies later and does not prevent those allocations by authenticated public peers. No transport-wide memory budget was introduced: legitimate large block sync remains compatible. This residual shared-RLPx exposure needs separate transport-budget work before making any total-memory guarantee for hostile public deployment.

## Reserved connections and topology

`p2p/reservations.go` validates at most 100 unique complete pinned enodes. With `ReservedPeerMode`, MaxPeers is a hard total including reserved, static and trusted connections. MaxPublicPeers must fit outside all reserved slots; zero means the automatic remainder, not an explicit zero budget. To configure zero public peers set MaxPeers equal to the pin count. Pins are immutable startup policy; removing an ordinary static peer does not remove a configured reservation. Change the startup configuration to remove a pin.

`p2p/server.go` applies quotas at both admission checkpoints. Reservation status is only exposed on Peer after the encrypted protocol handshake has authenticated the pinned node key. `p2p/dial.go:startReservedDials` gives pins an independently bounded reconnect lane; a full public pool or active public dials do not consume it. NoDial suppresses both lanes. The extra reserved lane can temporarily add up to MaxPendingPeers outbound handshakes, independently of public handshakes; established connections still obey the single hard cap. Inbound unauthenticated handshakes retain the existing bounded semaphore and are not a guaranteed DoS-free service; reserved outbound reconnect does not depend on that inbound semaphore.

The eth subprotocol uses the server's hard cap in reserved mode, including when light service is configured, so a second reduced eth budget cannot exclude reserved core sync. The relay subprotocol separately reserves configured pin cardinality within its own MaxPeers. BLS consensus admission is unchanged.

For 300–400 common nodes, use a bounded public degree (example 16), multiple independent gateway-reaching neighbors, and opt-in gateways (example 32 public peers plus two core pins). Committee examples use six pinned core identities plus 16 public slots, total 22. Populate discovery/bootstrap sets with diverse **common** peers. Two selected common static peers can provide initial reachability while dynamic discovery uses the remaining bounded dial budget; do not make every miner static-connect to every validator. Pins on committee members refer to the other core nodes' actual RLPx identities, not their BLS keys.

There are no global route advertisements or a proof that a random graph reaches a gateway within TTL. Operators must arrange and monitor at least two gateway-reaching paths within the configured hop budget. With four hops, origin→common→common→gateway works. Include distinct failure domains. More gateways or lower-degree neighborhoods improve route search latency. Normal validated eth block/keyblock synchronization supplies mining jobs; this change does not trust relay-provided chain heads or replace sync validation.

## Operator examples and validation

`examples/common.toml`, `gateway.toml`, and `committee.toml` are additive templates parsed by the real CLI TOML loader in `cmd/cypher/common_relay_config_test.go`. All enodes use documentation TEST-NET addresses and disposable public test identities: replace them before use. CLI settings can override TOML: inspect the final operator configuration before a later authorized launch.

With `TxQUIC.AutoRole = true`, startup prepares the durable TxQUIC engine and Common bridge but leaves the committee receiver closed. The existing `miner.start` flow verifies the local BLS key, then checks it against the current canonical committee and starts the receiver at the matching endpoint's TxQUIC port. A nonmember remains a Common node, including when it uses the same rnet port as a committee member on another machine. `CommitteePublicKey` remains accepted for old TOML compatibility but is ignored by automatic role selection; no separate identity configuration file is required. Keep using the existing account/BLS key-loading procedure. `miner.stop` closes and drains the receiver while the node-global WAL and outbox remain available for pending work and a subsequent `miner.start`.

Critical tests:

- `p2p/relay/relay_test.go`: actual negotiated Run/MsgPipe traffic, multi-hop concurrent dedup/reverse routes, forged response rejection, failover beyond initial fanout on NACK and timeout, no-route failure, TTL/size/rate/queue/cache limits, per-peer fairness, pending bytes independently of count, and joined shutdown.
- `eth/common_relay_test.go:TestCommonRelayTxRealCommitteeIngress`: actual loopback QUIC ingress Start/acceptLoop/handleStream, application ECDSA signatures, WAL/pool/StoreSync path, four distinct committee BLS ACKs and n-f bitmap accumulation, no origin/common direct clients, gateway pooling, original admission/reward preservation, mutated ACK rejection.
- `core/pow_result_relay_test.go:TestPoWResultRelayRealIngressRewardIntegrity`: actual loopback PoW QUIC ingress, real ColossusX tester seal and BLS receipt, origin→common→gateway routing, production all-member retry sender, duplicate suppression, receipt mutation and reward theft rejection. Chain-head admission uses a fixture callback; this is not a full running CandidatePool/chain experiment.
- `consensus/colossusX/candidate_seal_binding_test.go`: independent Python-generated codec preimage, compact/sidecar reconstruction, real work/reward mutation tests, old empty-preimage rejection, malformed encoding failure.
- `p2p/reservations_test.go`: actual admission checks under **400 attempted identities**, trusted/static hard caps, reconnect with public pool full, NoDial, config bounds. This is an in-process simulation, **not 400 launched processes**.
- Existing ingress outbox/quorum, PoW transport, sync, reward and reconfig suites provide regression coverage. No new full live/certified/recovery chain scenario or 400-process throughput/latency experiment is claimed.

Using existing RLPx avoids a second peer identity, discovery mesh, score engine, transport stack and resource manager. Gossipsub would still need authenticated request/response receipts, canonical target filtering, bounded reverse routing and durable source retry. It would not make a gossip acceptance ACK into committee admission. For this fixed destination workload the small negotiated protocol reuses the deployed stack and preserves application trust boundaries. Global route discovery, peer scoring and larger dynamic meshes remain possible future work, with their own validation requirements.
