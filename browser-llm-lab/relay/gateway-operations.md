# Public browser mesh gateway operations

This service provides regional access to owner-only Common sockets and authenticated outbound Common source uplinks, plus an optional signed endpoint directory and browser rendezvous. A browser can attach to up to 20 distinct Commons across local and remote gateways, and up to 20 direct WebRTC neighbors. Its home primary lease remains required; extra home Commons use child leases and remote Commons use independent leases at their verified HTTPS origin. One Worker and one explicit-ON browser budget cover all attachments. Discovery-enabled browsers use an ephemeral signing identity and at most four rendezvous WSS connections; compatibility mode retains the original single primary `/signal`. Gateway servers never relay Common-to-Common streams internally. The initial browser state is **OFF**. The current operational config retains the standard `common-mine` socket and enables `sourceUplink: {enabled:true,maxSources:32,maxSourcesPerClient:4}`. Remote Commons initiate WSS and prove native-key ownership; operators do not add every remote Common key to a list.

Startup remains rooted at the viewed page: the browser first loads the home `GET /relay/v1/mesh/config`, requires an enabled nonempty home-gateway Common list (pinned local sockets or authenticated source-uplink targets), and obtains its primary lease from the home `POST /relay/v1/mesh/sessions`. Discovery and signed browser-key rendezvous start only after that lease exists. Additional verified remote Common leases start after the home native WSS is connected and AI load is idle. A remote lease is independent at its issuing gateway but secondary to the home primary in this browser. There is no remote-primary fallback when the home gateway/Common is unavailable, and no serverless DHT bootstrap. Losing the home primary closes the browser's remote leases too and performs bounded fresh admission at the home origin.

The deployed origin is `https://ai-test.make-cph-great-again.community`. The gateway binds only `127.0.0.1:8091`. Nginx publishes only `/relay/v1/mesh/`; older `/relay/v1/` owner/header routes return 404. Existing page routing to port 8080 and TLS settings are preserved.

## Owned files and processes

Runtime modules are `/root/cypher/browser-llm-lab/relay/{gateway,discovery,source-uplink,config,geo,turn,main}.mjs`. The operational config is `relay/config.json` and the exact gateway process definition is `relay/gateway.ecosystem.json`. Configuration contains public Common identities and private socket/secret **paths**, not private signing keys or bearer tokens. Do not serve the operational config file as an asset: the public `config` endpoint returns its restricted projection.

The exact gateway app name is `cypher-browser-mesh-gateway`, with the separate PM2 home `/root/cypher/browser-llm-lab/.runtime/mesh-gateway/pm2`. The native source is the separately managed standard Common at `/root/cypher/config/browser-relay/common-mine.sock`, configured in `/root/cypher/config/browser-relay/common-mine.json`. Its sourceId is `common-mine`; its real node identity is read from that running Common and preserved in the gateway's local socket pin. Historical A/B fixtures are retained outside production startup. The dedicated TURN app is `cypher-header-turn` under the separate PM2 home `.runtime/relay-turn/pm2`; its reusable definition is `relay/turn.ecosystem.json`.

To inspect, start, stop or restart **only this gateway**, use:

```sh
PM2_HOME=/root/cypher/browser-llm-lab/.runtime/mesh-gateway/pm2 pm2 describe cypher-browser-mesh-gateway
PM2_HOME=/root/cypher/browser-llm-lab/.runtime/mesh-gateway/pm2 pm2 start /root/cypher/browser-llm-lab/relay/gateway.ecosystem.json --only cypher-browser-mesh-gateway
PM2_HOME=/root/cypher/browser-llm-lab/.runtime/mesh-gateway/pm2 pm2 stop cypher-browser-mesh-gateway
PM2_HOME=/root/cypher/browser-llm-lab/.runtime/mesh-gateway/pm2 pm2 restart cypher-browser-mesh-gateway --update-env
```

A gateway-only code/config rollout uses only the exact `restart cypher-browser-mesh-gateway --update-env` command above. A restart disconnects all current groups, their child leases and incoming source uplinks. Native sources reconnect with a fresh challenge, target generation and stream IDs; old sessions are not migrated. Browsers that remain enabled must obtain new primary and child leases while retaining their per-ON browser byte accounting. Coordinate restarts with active users and timed tests; native Commons, TURN, the page server and other PM2 applications are outside this restart. Never use global PM2 `save`, `resurrect`, `delete all` or `restart all` for this deployment.

`relay/start-managed.sh` and `cypher-browser-mesh.service` provide separately reviewed, exact-name boot integration for the two Web components, gateway and TURN. The managed launcher skips already-online owned apps. Its `stop` action stops only gateway and TURN; it neither starts nor stops the standard Common or historical A/B fixtures, so use the gateway-specific command above when only the gateway needs attention.

## Public contract and trust boundary

| Route under `/relay/v1/mesh` | Requirements and behavior |
| --- | --- |
| `GET /config` | Allowed frontend Origin or same-origin Fetch Metadata; public network, currently available local and authenticated source-uplink Common identities, limits, STUN and optional discovery paths/bootstrap origins. Creates no session. |
| `POST /sessions` | Allowed frontend Origin, body `{}` or optional active `sourceId` creates a primary group and its assigned Common lease. Body `{sourceId,attach:true}` plus the primary bearer adds one distinct active Common child in the same client group. Returns that lease's opaque token, native browser ID and expiry; child responses include `parentId`, primary responses include `maxAttachments`. |
| `WSS /source` | Explicit source-uplink enablement and exact gateway Origin. Fresh five-second challenge plus native-key signature and signed endpoint; a supported native capacity profile is required before the target becomes available. No browser bearer, arbitrary URL or TCP destination. |
| `WSS /connect` | Allowed frontend Origin; first message `{token}` with the gateway token. Gateway authenticates to its assigned Common over an owner Unix socket or authenticated source-uplink stream and preserves the native hello and subsequent text frame bytes. |
| `WSS /signal` | Allowed frontend Origin; first message `{type:"auth",id,token}` using the primary lease only. Child tokens cannot create signaling identities. Exchanges SDP/ICE only between assigned browser peers. Tokens in URL queries are rejected. |
| `GET /discovery` | Allowed frontend Origin or same-origin Fetch Metadata; at most 64 signed Common endpoints and 64 active signed browser records, within 256 KiB. |
| `POST /discovery` | Signed `{endpoint}` publication, 16 KiB body limit, 1 request/second and burst 4 per client. An unknown publisher Origin must be canonical HTTPS and equal the verified endpoint origin. No private URL forwarding. |
| `WSS /rendezvous` | Allowed frontend Origin; challenge, ephemeral browser-key proof, signed browser lease and signed SDP/ICE. Native lease tokens are not used on this socket. |
| `POST /renew` | Bodyless, valid Origin and the primary or child's own bearer; renews that private native lease and returns refreshed TURN credentials without resetting shared group accounting. |
| `DELETE /sessions` | Bodyless, gateway bearer, valid Origin; a child bearer releases only that child, while the primary bearer releases the entire group and its channels. |
| `GET /status` | Gateway bearer and valid Origin or same-origin Fetch Metadata; bounded status for that native endpoint, shared group byte/attachment accounting and aggregate fixed-enum gateway drop counters. |

Native Origin stays pinned to its configured value. Browser-facing native lease APIs and WebSockets allow the home origin plus `discovery.allowedOrigins`, without wildcard credentials. Native `/source` requires the gateway origin exactly. The signed endpoint self-publication exception applies only to `/discovery` POST and Content-Type-only preflight; it does not grant access to sessions or rendezvous. Every public lease maps to one private native token retained only in gateway memory. A native WebSocket close invalidates the corresponding public lease; an old token cannot revive it. Primary close, expiry, deletion or group-budget exhaustion releases all children. Child close, expiry or deletion releases only that attachment. Pending child admission reserves both the slot and source before asynchronous native work; if the primary disappears or the response is canceled, the newly returned native lease is released. Child tokens cannot create grandchildren, and an already attached or pending source cannot be attached again in that group. Node targets accept no user-supplied URL, IP, port or Unix path. Native hello public key and network must match the assigned local pin or authenticated source identity; a changed numeric native IP does not change that identity or authorize a gateway TCP dial. These endpoint checks do not constitute independent browser verification of native RLPx authentication. The browser independently verifies native secp256k1 advertisement signatures and signed endpoint claims, plus schemas, native session binding, network, route bounds and expiry. Native Commons independently verify advertisements and authenticate/decrypt the RLPx stream.

The native network can discover and connect ordinary Common peers without Web gateway registration. With discovery enabled, browser transit advertisements are verified cryptographically without a central key list. Public remote attachment requires a separate native-signed endpoint claim binding the Common key to the public HTTPS gateway origin and source. The directory automatically accepts valid unknown identities, and each browser verifies the same signature before contact. Regional local socket mappings remain explicit and restrict owner socket access. Alternatively, a Common with `mesh.gatewayUplink:true` and the configured `mesh.publicGatewayOrigin` initiates verified TLS WSS to `/relay/v1/mesh/source`; it needs no inbound public port, individual domain, separate Node.js gateway or manual key entry. The challenge proves possession of the native key, not a consensus role. A same-origin source discovered after browser ON is verified against fresh config and attached as a child under the existing home group budget.

Set `discovery.enabled:true`, `discovery.bootstrapOrigins` (up to eight exact HTTPS contact origins), and `discovery.allowedOrigins` (up to eight allowed HTTPS frontend origins). Configure the local Common's `mesh.publicGatewayOrigin` to the regional gateway's exact public origin. The gateway polls each fixed local socket's `/relay/v1/mesh/endpoint` every 30 seconds, verifies source/key/origin, and automatically publishes verified local envelopes to the configured bootstrap directories. Unknown Common keys do not need edits at those seed gateways. Absent or unsupported native `/endpoint` leaves the existing local mesh path available but provides no automatic public endpoint advertisement. See [discovery protocol](discovery-protocol.md) and [native handoff](common-endpoint-native-handoff.md).

Automatic publication performs HTTPS POST only to operator-configured seed origins, not origins learned from public directory entries. It uses at most two simultaneous requests, one attempt per node/seed per 30 seconds and per-seed pacing of one/second, a two-second total timeout and a 4 KiB response limit. TLS verification is enabled; redirects, credentials and bearer forwarding are absent. A signed publisher at a previously unknown Origin may POST only its own matching gateway-origin claim. Configured frontends may gossip other verified claims. These controls bound resource use but do not establish Sybil resistance or a Common's consensus role. Directory entries expire after at most 120 seconds; normal refresh is 30 seconds.

Rendezvous browser records use ephemeral secp256k1 keys, five-second nonce challenges, 120-second maximum leases and periodic signed renewal. Signaling signatures bind peer IDs, both session generations, sequence and at most 30 seconds of validity. The gateway verifies but cannot substitute unsigned SDP/ICE. Browser self-signatures identify that browser key; they do not prove ownership of the Common identity named in its record. Up to 20 ring-neighbor records are introduced per visitor, including late arrivals. A browser uses up to four rendezvous origins and acquires remote native leases separately; its home bearer is never sent to another origin.

Only Nginx supplies trusted `X-Relay-Client-IP` and `X-Relay-Country`. Its Cloudflare CIDR allowlist gates `CF-Connecting-IP`/`CF-IPCountry`; direct requests use their actual address and have unknown country. Incoming trusted-header values are overwritten. The loopback service assumes requests originate from this trusted proxy; do not expose port 8091 or give untrusted local processes access to its private Unix sockets.

Geo is optional country-level display-anchor data labeled `accuracy:"country"`; it uses no browser GPS, external geo API or per-peer IP disclosure. Unknown country remains `null`. Keep the Cloudflare allowlist current using the provider's published IPv4 and IPv6 ranges.

For the country header alone, the Cloudflare zone operator must enable **Network → IP Geolocation → On**. The **Add visitor location headers** Managed Transform is an alternative, but its city/latitude/longitude headers are unnecessary for this country-only map. `CF-IPCountry` is sent to the origin as a request header; its absence from the browser's response headers does not establish that the setting is off. [Cloudflare IP geolocation](https://developers.cloudflare.com/network/ip-geolocation/), [managed transforms](https://developers.cloudflare.com/rules/transform/managed-transforms/reference/).

The country-anchor table now covers249 country/territory codes, expanded from16; source attribution, pinned download hashes and omissions are documented in [geo-data.md](geo-data.md) and `geo-data-sources.json`. A missing country header, an untrusted proxy peer, an unsupported country code, or Cloudflare's special `XX`/`T1` codes yields `null`. Unknown participants appear in a separate non-geographic map area. An unknown map marker cannot distinguish these causes without retained trusted request metadata. The country header for a past iPhone admission was not retained, so its exact cause remains unverified. `CF-RAY`'s data-center suffix identifies Cloudflare infrastructure and must never be used to invent the participant's country or coordinates. [Cloudflare HTTP headers](https://developers.cloudflare.com/fundamentals/reference/http-headers/).

## Current capacity and cleanup

- 80 public leases total shared across all pinned local Commons and authenticated source-uplink targets, at most 80 leases plus pending admissions per updated Common, at most 80 native leases plus pending admissions plus discovery visitors combined per client address, 384 gateway TCP connections, at most 20 distinct Common leases per browser group including the primary, and at most 20 assigned direct RTC peer edges per browser. Native and rendezvous admissions count the same client occupancy in either order, including pending native work. Primary and child leases both consume these lease counts; 80 per client address does not mean 80 groups with 20 children each.
- 5-minute renewable primary and child leases; browser renewal after about 2 minutes with staggered child renewals. Native expiry and local expiry are both enforced. A canceled admission or failed initial response releases the newborn native lease because the browser never received a token. Primary loss triggers whole-group browser readmission; secondary loss removes its circuits and queues while other Common sockets and RTC peers remain, followed by bounded retry with a fresh child identity. OFF, hidden/freeze and page exit close the whole browser group; old callbacks cannot revive it. Native lease expiry is the backstop for an unavailable private endpoint.
- 1 KiB native-lease HTTP body and separate 16 KiB signed-discovery publication body, 8 KiB headers, 16 KiB ordinary native response/frame and separate64 KiB native status response, 32 KiB signaling frame, 64 KiB native/signaling send-buffer limits, and 64 ICE candidates per signaling route. Compatibility `/signal` resets both directions on a fresh offer; discovery rendezvous resets the offering sender's route counter on its new offer. The answerer's discovery counter remains scoped to its current destination route until that route is removed or its own offer resets it.
- 128 shared HTTP requests/second with a 256-request burst; 32 requests/second per address with a 64-request burst; 32 admissions/minute per address. Native HTTP requests are bounded at 16/second per Common. Native admissions separately use1/second with burst8. Metadata HTTP concurrency is limited to8 per Common with no idle keepalive sockets. Status/config requests are coalesced with bounded freshness to avoid identical requests from80 clients consuming metadata capacity. Session HTTP requests are bounded at 8/second.
- Each gateway-local native lease group, authenticated HTTP traffic and compatibility `/signal` share the group outgoing 64 KiB/second bucket and one group incoming 64 KiB/second bucket. Each direction allows a 128 KiB burst. Adding a child does not add bandwidth. Shared gateway traffic, including source-uplink outer packets, discovery HTTP, publisher bodies and rendezvous messages, is bounded at 1 MiB/second with a 2 MiB burst. Signaling ingress retains its separate 4 KiB/second subbudget and 10-message/second limit.
- Each browser group has one 100 MiB total payload budget across all native attachments, signaling and authenticated HTTP traffic. Adding/removing/renewing a child does not reset gateway accounting. Transfer-budget exhaustion releases the primary and all children. The browser separately retains its 100 MiB explicit-ON budget, including RTC payloads, across automatic group readmission. Accounting covers application payloads, not TLS/IP overhead.
- The one Worker shares 40 endpoint/transit/opening circuits, 4 pending opens per direction/type and 8 total, a 4 MiB application reservation, a 512 KiB temporary queue and 64 outgoing queued/pending frames across all native and RTC connections. Each attachment also respects its negotiated native circuit profile. Idle JSON send/receive rates stay 48/64 KiB/s; generation uses 24/32 KiB/s and at most one circuit; model load/benchmarking closes circuits and permits bounded control at 4/8 KiB/s. The controller separately caps aggregate native plus RTC `bufferedAmount` at 512 KiB.
- Advertisement fanout uses bounded, accounted endpoint/node references and coalesces the best eligible route before materializing shared queue frames. Control has a 24 KiB/s subbudget within the unchanged applicable global Worker send rate. The isolated 20-by-20 fixture sent 400 RTC plus 380 native advertisements and heartbeat traffic totaling 666,316 JSON bytes in 26.5 simulated seconds, with peak application reservation 1,453,050 bytes and queue 36,250 bytes. The earlier 4 KiB/s control allowance would not carry this fanout within the native 30-second advertisement refresh interval. These are fixture measurements, not LIVE acceptance or browser process RSS.
- Native Ping is forwarded to the browser and the matching browser Pong is forwarded upstream; proxy automatic Pong is disabled. Pending Pongs expire after 15 seconds. Browser network-stack Pong is not proof that JavaScript or a Worker is making progress.

Source uplinks also add no browser lease or bandwidth allowance: the configured 80 native-backed browser leases remain shared across all local and source-uplink targets. This deployment accepts at most 32 source sockets and four per client address, within the same 384-connection and 1 MiB/second gateway limits. The combined local/uplink target registry is capped at 64. Authentication is bounded to eight pending sources globally and two per client, with one new source handshake/second and burst four per client. The source outer packet ceiling is 96 KiB; each direction allows 384 KiB/second with a 512 KiB burst and 128 messages/second with burst256. Queued plus outstanding writes share 64 packets / 512 KiB and a two-second write deadline. At most eight typed metadata requests and 80 native WS streams exist per source. Native metadata has a two-second deadline and the gateway allows three seconds before ending an unresponsive source. Source Ping/Pong is five/fifteen seconds; inner native Ping/Pong still traverses the browser causally. Native inner frame, stream, circuit and bandwidth limits are unchanged.

The source transport permits only the fixed mesh config/status/session/renew requests and fixed native connect streams; it exposes no arbitrary RPC, TCP, host, port or filesystem destination. It retains signed endpoint bytes unchanged. Source disconnect or endpoint expiry stops admission, withdraws the target and removes its affected browser sessions; a lost primary removes its group, while a lost secondary removes that child. Pending callbacks remain bound to the old target object and cannot affect a replacement. Sources revoke only their uplink-owned native tokens on disconnect. Stream IDs are never reused within a source generation; after 4096 IDs a fresh source connection is required. The existing native reconnect loop supplies new challenge/session/stream generations. Source lease metadata and stream state are RAM-only.

Discovery rooms add no native lease capacity. Visitors share the existing global TCP limit and per-address admission count; at most `maxSessions` rendezvous visitors are active. Each visitor has 4 KiB/second incoming and outgoing metadata budgets, 32 KiB bursts, 32 KiB frames, 64 KiB / 64-frame pending output, 10 messages/second and 20 live signaling destinations. Peer-list updates coalesce and queued signals from departed generations are discarded. A valid signed signal to a departed, expired or superseded recipient is dropped after replay-history validation without disconnecting the healthy sender. `droppedUnavailableSignals` counts those drops; `rejectionReasons` contains twelve fixed, saturating diagnostic counters and no peer identifiers or message content. A bounded replay history persists for the signed lifetime and clock skew. Client-address discovery transfer totals are retained while active, limited to 100 MiB; the browser enforces its stricter global per-ON budget across gateways. Directory and rendezvous metadata RAM is separately bounded from the browser Worker's 4 MiB application reservation. Browser-key and endpoint leases are RAM-only and are not durable registration accounts.

At browser OFF, `DELETE /relay/v1/mesh/sessions` is sent to the home origin with the home primary bearer and separately to every remote issuing origin with only that remote bearer. The home DELETE releases home children; it has no authority over remote gateway leases. WSS/RTC are closed immediately, discovery queues and ephemeral browser keys are discarded, and late asynchronous admission results are released rather than adopted. DELETE is best effort; socket/heartbeat/lease cleanup covers sudden loss. Recovery while still enabled retries home admission; explicit OFF or background suspension requires a fresh user ON.

PM2's 128 MiB gateway and 96 MiB TURN memory restart settings are process supervision thresholds, not hard kernel memory isolation. Admission and application buffers remain independently bounded.

## TURN and inspection

TURN REST credentials are issued only in authenticated session/renew/signaling responses, expire after 300 seconds, and derive from the owner-only `.runtime/relay-turn/rest-secret` file. Public GET config never includes credentials or the secret path. Dedicated TURN listens on UDP/TCP 34790 with relay ports 49180–49211, per-user allocation limit 6, global allocation limit 64, 64 KiB/second allocation bandwidth and 2 MiB/second aggregate bandwidth per direction. Private, loopback, link-local and multicast destinations are denied; TLS/443 TURN and anonymous allocations are not enabled.

Authenticated `status.gateway.dropReasons` and programmatic `gateway.stats().dropReasons` contain copied, saturating integer counters from a fixed finite set. `upstream_closed` means the native socket closed; it does not identify the native internal cause. `native_capacity`, `signal_capacity` and `pong_timeout` identify gateway-side capacity/heartbeat decisions. Counters reset on gateway process restart and contain no session IDs, IPs, tokens or frame contents. Historic native Attach errors are not logged by the native handler, so do not infer a past native rejection reason from an opaque socket close.

`node --test tests/relay-gateway.test.mjs tests/relay-discovery.test.mjs tests/relay-source-uplink.test.mjs` exercises isolated Unix WebSockets, exact frame forwarding, auth/origin/capacity boundaries, primary/child group lifecycle and shared budgets, private TURN issuance, canceled or bandwidth-rejected admission cleanup, causal Ping/Pong and diagnostic counters. Source fixtures additionally verify native challenge/signature binding, automatic unknown-identity admission, 20 distinct Common leases under one group, exact bytes/Ping/Pong, expiry, late-message cleanup, source/IP/frame limits and the 4096-ID boundary. These use synthetic native endpoints and do not establish real native RLPx throughput. Discovery fixtures also verify unknown signed endpoint admission, bounded caches, self-publication Origin policy, publisher URL confinement, two-gateway authenticated rendezvous, replay/expiry, ring-neighbor limits and cleanup. Mocked outbound-publisher response tests are labeled as unit checks, not real Internet delivery. A separate actual TLS publication fixture adds only test-process DNS resolution and test-CA trust: production publishing sends the signed local endpoint through a verified HTTPS connection, and a second gateway accepts the unknown Common without key or publisher-Origin registration. It asserts authorized TLS and SNI, exact envelope bytes and no bearer forwarding. This is same-host transport acceptance, not public Internet reachability. These fixtures establish gateway behavior; actual browser-mediated native RLPx, external-network reachability and timed soak acceptance require the separate mesh browser report.
