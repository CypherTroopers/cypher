# Common browser mesh

Current deployment: [Automatic outbound Common source uplink](common-endpoint-native-handoff.md#外向きsource-uplinkによる自動接続2026-10-03) and the [Cypher directory consolidation](consolidation-20261003.md). The earlier [discovery verification](discovery-update.md) and capacity/map reports retain their original test conditions.

This is the web implementation of the revised 2026-10-03 [native contract](/root/cypher/docs/common-relay/browser-public-header-relay-spec.md). It replaces the earlier public-header gateway. The native header exporter remains available in Cypher as an optional private feature; this deployment does not publish its API.

```text
Common(s) -- Unix socket / outbound source WSS -- gateway -- browser A
                                                                |
                                                   up to 20 direct WebRTC peers
                                                                |
Common(s) -- Unix socket / outbound source WSS -- gateway -- browser B
```

Each Common authenticates and encrypts the existing RLPx stream. Browsers relay opaque chunks and carry route advertisements; they do not hold native secrets, become native peers, vote, mine or receive rewards. Eligible Common miners are allowed by the native role policy. Browser code verifies native secp256k1 advertisement signatures, network, expiry, strict schemas and resource limits. It also verifies separately signed public endpoint claims before contacting another region. Native endpoints independently verify advertisements and perform RLPx authentication. The original advertisement payload bytes and signature are preserved. There is no Common-to-Common forwarding path inside the gateway and no gateway-only browser fallback.

## Running deployment

The page is `https://ai-test.make-cph-great-again.community/`. `/healthz` reports workspace `cypher-v5`. Node ON explicitly starts participation; Node OFF, page exit, hidden or freeze tears down Worker, WSS and RTC, clears temporary buffers and requires a new explicit ON. Losing the primary native attachment while the page is still active releases the entire browser lease group and triggers bounded fresh admission with new native/browser sessions. A secondary attachment failure releases only that Common and its circuits, then retries that source with a fresh lease while other attachments and RTC peers remain available. Neither path can revive an OFF generation.

The gateway binds only `127.0.0.1:8091`. Nginx proxies `/relay/v1/mesh/` over the existing HTTPS virtual host and rejects the other `/relay/v1/` paths. `nginx-site.conf` is the installed configuration record; the original root page proxy and TLS settings are preserved. Native sockets and IPC never become public URL targets. Existing page server `server` remains on `127.0.0.1:8080`.

Operator configuration is `relay/config.json`: fixed chainId10101919, genesis `0x001c8239f25a697933e2a54511a576205fb21cbb80dc974adb29894dc80250ad`, the standard `common-mine` identity and its owner-only Unix socket `/root/cypher/config/browser-relay/common-mine.sock`. These mappings authorize local socket access; they are not a network-wide registry of remote Common identities. Native origins are exactly the public HTTPS origin. Native lease requests select only an active source ID from the operator-pinned local sockets or authenticated source-uplink targets; a gateway never opens an arbitrary client-supplied URL, host, port or filesystem path. Browsers independently follow verified public endpoint claims to remote gateways. The standard Common keeps its existing `/root/cypher/chaindbmine` datadir and identity; the gateway never opens its chain database. See [native operation details](mesh-native-operations.md), [current local identity pin](config.json), and [gateway operation details](gateway-operations.md).

The production source is the standard Common managed from `/root/cypher`, initialized for the network in `/root/cypher/genesis.json`. Its configuration is `/root/cypher/config/browser-relay/common-mine.json`; the configured public gateway origin must equal this site's HTTPS origin. The canonical Linux executable is `/root/cypher/build/bin/cypher-linux-amd64`. Native startup/restart is separate from the Web service helper. Do not reset or merge its existing database or identity.

Earlier research acceptance used dedicated Common A/B, with B isolated in a loopback-only network namespace. Their datadirs, identities, old binaries and evidence are preserved as explicit test fixtures. They are not production gateway targets and the Web startup unit does not launch them. A future two-Common relay test must explicitly prepare distinct native endpoints; two browsers connected to one Common do not establish Common-to-Common relay. Historical results remain in [native operation details](mesh-native-operations.md) and their original evidence paths.

## Runtime and boundaries

Install pinned web runtime dependencies with `npm ci --ignore-scripts` (Node22 or later). Start the gateway using `node relay/main.mjs /root/cypher/browser-llm-lab/relay/config.json`; normal startup neither changes Nginx nor starts native nodes. Configuration is strict bounded JSON with no symlink components. Tokens and TURN secrets are runtime-only and must never enter browser assets, source control, logs or URLs.

Public APIs are version1:

| Path under `/relay/v1/mesh` | Operation |
| --- | --- |
| `/config` | Public fixed network, current local and authenticated source-uplink Common identities, limits, STUN and optional discovery bootstrap paths/origins; does not participate |
| `/sessions` | POST empty/{} or active `sourceId` creates the primary native lease and browser group. POST `{sourceId,attach:true}` with the primary bearer adds a distinct Common child lease. DELETE a child bearer releases that child; DELETE the primary bearer releases the whole group. |
| `/source` | Opt-in native source WSS; exact gateway Origin, fresh challenge and native-key proof plus signed endpoint. Adds a dynamic target after its capacity profile is verified; no browser bearer or arbitrary destination. |
| `/connect` | Native WSS; first message within3s is `{"token":"gateway-token"}`; gateway replaces only this authentication token upstream |
| `/renew` | POST the corresponding primary or child bearer to renew that live native lease and short-lived TURN credentials |
| `/signal` | Retained compatibility WSS for assigned local peers when discovery is disabled; primary bearer required. |
| `/discovery` | GET bounded signed Common endpoints and browser records. POST `{endpoint}` publishes a cryptographically verified Common endpoint without central key registration. |
| `/rendezvous` | Independent WSS browser-key challenge authentication; signed peer records and signed SDP/ICE across visitors to this gateway. No native lease or private key is needed to register a browser record here. |
| `/status` | Authenticated native endpoint status plus shared browser-group byte and attachment counts; no secret token |

Each enabled browser owns a primary native lease at its home gateway, one Worker and at most 20 distinct Common WSS attachments in total. With discovery enabled, an ephemeral browser signing identity opens at most four rendezvous WSS connections instead of the legacy single `/signal` connection. Additional home-gateway Commons use child leases with the existing shared group budgets. A remote Common uses its own independent lease at the signed remote HTTPS origin; its bearer is sent only to the origin which issued it. All browser attachments and RTC peers share the Worker and explicit-ON budgets. The idle browser fills verified targets gradually. The single configured local Common does not restrict the discovery directory to that identity, but unavailable, expired or unreachable endpoints can leave actual counts below the ceiling.

The initial lease must come from the viewed page's home gateway: `GET /relay/v1/mesh/config` must expose an enabled nonempty home-gateway Common list (local sockets or authenticated source uplinks), then `POST /relay/v1/mesh/sessions` must succeed before discovery is constructed. A verified remote endpoint supplies an additional attachment after the home native WSS is connected and AI load is idle; it cannot replace an unavailable home primary at startup. Primary loss closes remote attachments too and retries admission at the home gateway. This implementation has no remote-primary bootstrap fallback or serverless DHT. Bootstrap origins are contact hints, not trusted identity lists; reachable regional HTTPS/WSS gateways and their frontend Origin policy are still required.

On OFF, the browser closes all WSS/RTC connections and issues best-effort `DELETE /relay/v1/mesh/sessions` requests: each remote lease uses only its own remote origin and bearer, and the home primary bearer deletes its home group including local children. Network failure or abrupt page termination relies on socket closure, heartbeat and lease expiry for cleanup. Returning to a visible page does not automatically switch participation back on.

Native text frames pass unchanged through the gateway. The Worker selects a native attachment by cryptographically verified target node ID, replaces `session` for that connection, and maps only the unsigned route label between its canonical RTC browser ID and the native attachment's browser ID. Circuit ID, sequence, ciphertext and exact signed advertisement bytes remain intact. Local Common advertisements go to RTC peers; received peer advertisements can reach other local Commons, including when their source Common also has a local attachment. The Worker does not open a circuit directly between two local native sockets. WebRTC uses an ordered, reliable DataChannel. Credit is forwarded as flow control; it is never invented by a conforming browser.

Each primary and child lease lasts five minutes and renews after about two minutes, with staggered child renewals. Native disconnect invalidates that lease; primary deletion, expiry or disconnect also removes its children. A secondary loss leaves the primary signaling identity and unrelated RTC/native circuits alive. Reconnection starts a new native/browser session and RLPx circuit; a removed attachment ID or old frame cannot restore the old connection. The proxy forwards native Ping/Pong causally instead of keeping a dead browser alive with an automatic upstream pong. Circuit lifetime is30minutes, followed by new RLPx authentication; no stream migration is attempted.

Origin is an extra boundary, not authentication. Native lease APIs and WS require the home origin or an explicit frontend in `discovery.allowedOrigins`. Discovery POST additionally accepts a canonical public HTTPS publisher Origin only when the verified endpoint claims that same gateway origin; its preflight permits Content-Type only, without credentials or Authorization. Other cross-origin requests retain the configured frontend checks; same-origin metadata GET can use browser Sec-Fetch-Site when Origin is absent. Native requests always include the fixed native Origin. Public config may be read without joining. Active tokens authorize status/renew/delete. The gateway keeps private native tokens in memory, uses separate unpredictable public credentials and clears them on expiry, disconnect or shutdown.

## Capacity and accounting

Native ceilings remain those in the upstream specification. The gateway configuration permits 80 native-backed public leases total, shared across the local Common and all authenticated source-uplink targets, 80 combined native leases, pending admissions and discovery rendezvous visitors per client address, 384 TCP connections, up to 20 distinct Common leases per browser group, and at most 20 direct RTC neighbors per browser. Primary and child leases both consume the global, client and Common admission slots; the client ceiling counts both native leases and discovery visitors, not browser groups. The check applies in either admission order and includes pending native admissions. With discovery disabled, it retains the previous native-lease-only behavior. Each Common independently caps 80 native leases and 88 owner-socket connections. The gateway verifies the native capacity profile before admitting a session and paces each Common to 1 admission/second with burst 8; concurrent capacity does not imply simultaneous admission. Unknown keys/types, duplicate JSON keys, invalid integers, oversized messages, unassigned peers, old sessions, sequence violations, expired advertisements and excess queues are rejected.

Within each gateway, the native lease group, authenticated HTTP traffic and compatibility `/signal` share that group's budgets: 64 KiB/s per direction with a 128 KiB burst, and 100 MiB cumulative application payload. Adding or renewing a child cannot create a new group allowance. Exceeding the group transfer allowance releases the root and all children. Browser readmission retains the separate 100 MiB explicit-ON budget, including direct RTC payloads.

Browser limits:

| Resource | Normal | AI generation | Model load / benchmark |
| --- | --- | --- | --- |
| JSON send / receive, all attachments and RTC peers together | 48 / 64 KiB/s | 24 / 32 KiB/s | Stream DATA paused; 4 / 8 KiB/s control scheduling |
| Direct RTC peers / distinct native Common attachments | Up to 20 / 20; available population and verified endpoint reachability can lower actual counts | Existing connections retained; new admissions/RTC handshakes deferred | Existing control connections retained |
| Total browser circuits, including endpoint/transit/opening | 40 shared | 1; no new RTC handshakes | Existing circuits closed |
| Common endpoint circuits, across all attachments | Up to 40 within the same total, each attachment's negotiated native profile and each Common's shared 40 | Up to 1 total | 0 |
| Shared temporary queues | 512KiB; outgoing queued/pending64frames, input128frames | Same bounded ceilings | Cleared circuits |
| Opaque chunk / full JSON frame | 8KiB /16KiB | Same | Same |
| Pending hop receipts / log events | 128 /128 | Same | Same |
| Application reservation budget | 4MiB | Same | Same |
| Per explicit ON lifetime | 100MiB of application messages, across automatic readmissions | Same | Same |

These are bounded application payload/reservation budgets, not browser process RSS or billed network usage. TLS, SCTP, retransmission and browser implementation buffers are outside this meter. The controller additionally bounds aggregate native plus RTC `bufferedAmount` at 512 KiB; backpressure closes affected transports/circuits rather than growing RAM indefinitely. Advertisement fanout is coalesced as bounded, accounted endpoint/node references and only materialized into the shared frame queue as capacity allows. Control has a 24 KiB/s subbudget within the global send rate, so control and DATA together still cannot exceed the applicable Worker rate. This raises the earlier 4 KiB/s control allowance because 20 sources fan out to 20 RTC peers and received source advertisements also reach other local Commons. The isolated 20-by-20 Worker fixture emitted 400 RTC plus 380 native advertisements and heartbeat traffic totaling 666,316 JSON bytes in 26.5 simulated seconds; its peak reservation was 1,453,050 of 4,194,304 bytes, with 36,250 of 524,288 queued bytes and 52 of 64 queued/pending frames. That fixture verifies bounded scheduling, not LIVE throughput.

The revised encrypted-stream path needs different rates from the old header-only plan:24KiB/s JSON allows roughly18KiB/s base64 raw stream, while the native deadline assumes16KiB/s minimum. All admitted circuits share the same normal48KiB/s budget; increasing circuit count does not multiply throughput. This remains a best-effort supplementary route; full-duplex contention, AI load, oversized native frames or slow networks can cause native deadlines/reconnection. Full synchronization of arbitrary maximum-size blocks is not guaranteed.

The main Browser peers and Common connections counters show actual current connections as integers. Browser peers counts open direct WebRTC DataChannels; Common connections counts this browser's currently authenticated native WSS attachments to distinct verified Commons. Common relay circuits counts open endpoint transport circuits, excluding pending opens. Capacity is shown separately in the collapsed Connection limits & counting details. These counters are local observations, not the global Common population or independently verified native peer counts. UI measurements also distinguish native WSS JSON received, RTC application bytes received/queued, opaque raw bytes forwarded, native flow-control credit, hop ACK count/bytes, current queues, source advertisements, RTC getStats and measured direct/TURN path. A successful send() is not a receipt. A hop receipt binds both browser sessions, circuit, direction, sequence, exact ciphertext digest and length; duplicate/old-session receipts do not increase counters. The recipient acknowledges acceptance into its bounded next-hop queue, not downstream Common consumption. Neither browser ACK nor unsigned native credit proves chain adoption or finality.

Each native Common shares 40 circuits across all its 80 sessions, including opens that have not completed. Browser endpoint and transit circuits share one separate 40-circuit Worker ceiling across all native attachments and RTC peers. Pending opens are bounded to 4 per direction/type and 8 total across the same Worker. Generation permits one total circuit; model loading/benchmarking permits zero. A legacy Common's negotiated smaller endpoint limit still applies to its own attachment. Worker telemetry reports applied connection, circuit, byte and rate limits alongside current counts. A regional gateway supports at most 64 targets in total across local socket mappings and authenticated source uplinks; its separately bounded discovery cache holds at most 64 verified endpoints. A browser attaches to at most 20 distinct Commons in total. This installation retains one ordinary local Common socket mapping and accepts up to32 authenticated outbound sources; no remote node-key list entry is required. Actual available identities determine the count. The20-source fixture proves admission, not sustained20-Common native load. [capacity-update.md](capacity-update.md) and historical verification/evidence files retain their original test scope.

## Automatic discovery and regional gateways

Discovery is opt-in with `discovery: {enabled:true, bootstrapOrigins:["https://seed.example.org"], allowedOrigins:["https://browser.example.org"]}` in each gateway's operational config. Both lists have at most eight exact HTTPS origins. The bootstrap list provides initial contact locations, not trusted Common signing keys. Operators may retain owner-local socket mappings, or enable `sourceUplink` to accept Commons which initiate authenticated WSS at `/relay/v1/mesh/source`. The shipped native launcher config enables that outward connection to this public gateway. Operators permit the frontend origins which may acquire leases. Central operators do not add every remote Common public key or socket to a global allowlist.

The gateway also accepts and refreshes exact signed endpoint envelopes over authenticated native source uplinks. Such targets disappear on transport loss/expiry; duplicate pinned or active native identities are refused. The gateway polls private `GET /relay/v1/mesh/endpoint` from its owner-local Common sockets every30seconds, with at most two polling requests at once and existing native HTTP budgets. The response must be an exact signed envelope matching the local Common identity, source ID and this gateway's public origin. A Common without this optional API returns no endpoint; its existing local mesh attachment still works. The new native configuration field is `mesh.publicGatewayOrigin`; see [the native implementation handoff](common-endpoint-native-handoff.md) and [discovery protocol](discovery-protocol.md).

A verified local endpoint is automatically POSTed to configured bootstrap origins only, skipping self. Each node/seed pair is attempted at most once per 30 seconds; each seed gets at most one attempt/second. There are at most two outbound HTTPS requests, a two-second deadline, a 4 KiB response cap and no redirects or credentials. Public directory records never become server-side dial targets. The directory accepts an unknown Common's self-signed endpoint after signature, fixed-network, generation, expiry and publisher-Origin checks. This authenticates a key's endpoint claim; it is not global reputation, role certification, proof of reachability or Sybil resistance.

Browsers fetch bounded directories, independently verify exact signed bytes and maintain a RAM-only 64-endpoint cache with expiry, sequence rollback and retired-boot protection. A remote attachment must match the signed source, node ID and Common boot ID in the authenticated WSS hello. Endpoint expiry or boot/origin changes retire that remote attachment. Native advertisement signatures are also checked before Worker routing, so newly discovered Common advertisements need no central public-key pin. Native RLPx and admission policy remain authoritative for authenticated native communication and role restrictions.

Browser introductions use ephemeral self-signed records valid for at most 120 seconds and renewed approximately every 30 seconds. Each rendezvous authenticates possession of that browser key with a fresh five-second nonce challenge; a copied public record alone cannot log in. The key identifies a browser session, not ownership of its claimed Common affiliation. Signed offers/answers/ICE bind sender, recipient, both browser generations, sequence and a 30-second expiry. Rendezvous listings use at most 20 neighboring browser identities in a sorted ring so late arrivals remain discoverable. Browsers may join up to four gateways and contact a peer at a mutually available rendezvous; real stream bytes still travel over ordered reliable WebRTC.

Browser challenge signing tolerates the existing bounded 10-second discovery clock difference; the gateway still enforces its own strict five-second nonce expiry. Delayed SDP/ICE failures may close only the same peer instance in the current ON generation. The [2026-10-04 Chrome/TURN regression evidence](evidence/cross-browser-20261004/README.md) records the clock-skew reproduction, public WebRTC verification and untested real-device/network conditions.

Directory output is at most 256 KiB, at most 64 Common envelopes and 64 active browser records. Rendezvous rooms respect gateway/global/IP connection and admission budgets; each visitor has 4 KiB/s per direction, 32 KiB bursts, 32 KiB frames, 64 KiB / 64-frame queues, 10 received messages/second and at most 20 live signal destinations. Peer-list updates coalesce; departures remove stale queued signals; replay high-water marks survive short reconnects. Five-second Ping and 15-second Pong silence bounds reclaim abandoned visitors. These bounded discovery metadata structures are separate from the Worker 4 MiB reservation. The browser's 100 MiB explicit-ON accounting includes discovery HTTP, native traffic, all rendezvous connections and RTC application payload.

Ordinary native Common P2P membership never requires this Web gateway. Internet-reachable HTTPS/WSS, TLS certificates, permitted frontend Origins and at least one reachable bootstrap are operational prerequisites for regional browser attachment; an owner-only Unix socket is not itself an Internet service. The checked-in tests distinguish cryptographic and gateway fixtures, actual WebRTC across separate HTTPS origins, and subsequent public/live acceptance. Historical reports do not establish deployment of this discovery revision.

## World map

The map uses the existing Natural Earth public-domain land outline. Country display anchors cover249 country/territory codes from attributed sources; see [geo-data.md](geo-data.md). These are coarse country estimates, not device positions. Nginx overwrites client-supplied metadata and trusts CF-IPCountry / CF-Connecting-IP only from configured Cloudflare CIDRs. No GPS or external geolocation lookup is performed. Missing or unsupported location metadata stays unknown in a separate, explicitly labeled location-unavailable area; it never receives invented coordinates. A VPN can change the country estimate. Direct WebRTC can reveal connection IP addresses to peers.

Each connected browser has its own visible pin, including browsers in the same country. Same-country pins use small offsets around the actual country anchor; only their label cards move farther to avoid overlap. The map draws at its actual CSS size so pins and text stay readable on phones. Static lines show connections. Moving cyan lights mean actual received chunks, orange lights mean successful DataChannel send-queue submission, and green lights mean received browser hop ACKs. Sending and receiving an ACK remain separate measurements. No traffic event means no invented moving traffic. Reduced-motion preferences replace animation with a static activity badge. Animation is limited to30fps/24 simultaneous pulses and stops when idle, offscreen, hidden or OFF. See [map-update.md](map-update.md) for this revision's isolated renderer fixtures and separate public-browser acceptance.

## Optional authenticated TURN operation

Server-only configuration accepts `turn: {urls: ["turn:13.140.169.170:34790?transport=udp", "turn:13.140.169.170:34790?transport=tcp"], secretPath: "/root/cypher/browser-llm-lab/.runtime/relay-turn/rest-secret", ttlSeconds: 300}`. Omit `turn` to disable the issuer. The secret file must belong to the service UID, have exactly mode 0600, contain 32–128 ASCII letters/digits/underscore/hyphen, and have no linked path components. The gateway refuses invalid secret files before listening. The secret is provisioned separately, remains in the ignored runtime directory and is never copied into `relay/` or the browser bundle. Do not put a secret on a process command line.

Public `GET /relay/v1/mesh/config` returns STUN entries and `turnEnabled`, with no TURN credential, URL or secret path. Explicit session creation and authenticated HTTP renewal return an ICE entry using coturn's [REST authentication protocol](https://github.com/coturn/coturn/blob/4.18.0/examples/etc/turnserver.conf): username `expiryEpoch:peerId` and base64 HMAC-SHA1(secret, username). The effective expiry never exceeds the five-minute lease, even if the configured credential TTL is larger. Renewal issues credentials for subsequent connections; an established DataChannel is not restarted solely to update credentials. Ending a browser session closes its RTC connections. Issued credentials cannot be recalled individually and expire within their bounded lifetime; coturn allocation refresh lifetime is separately limited.

The dedicated runtime builds [coturn 4.18.0](https://github.com/coturn/coturn/releases/tag/4.18.0) from the official HTTPS tag archive, with extracted build dependencies rather than a global package/service install. The distribution's 4.6.1 candidate predates the official [mobility quota](https://github.com/coturn/coturn/security/advisories/GHSA-f6hc-79w3-p8pq) and [IPv6 address-range](https://github.com/coturn/coturn/security/advisories/GHSA-4v97-rxjj-4f99) fixes. Source/package archive checksums are recorded under `.runtime/relay-turn/build-info.json`; recording a downloaded archive's checksum does not independently authenticate its publisher. The dedicated binary and copied dependent libraries live under `.runtime/relay-turn/coturn-4.18.0`, with an owner-only configuration and start script.

This instance listens on IPv4 `13.140.169.170` and loopback, UDP/TCP port 34790, with UDP relay ports 49180–49211. It requires REST authentication, permits at most six allocations per peer and 64 allocations globally, and limits an allocation to 64 KiB/s and the server to 2 MiB/s in each direction. Finite relay ports may constrain actual capacity below the allocation quota. Maximum allocation refresh lifetime is 300 seconds and establishment timeout is ten seconds. Private, loopback, link-local and multicast peer destinations are denied. TCP relay allocations, TLS client listeners, anonymous STUN, dynamic database lookups, mobility, CLI and web administration are disabled or left disabled by default. UDP/TCP TURN carries end-to-end encrypted WebRTC DataChannels; this configuration supplies no `turns:` listener or TLS/443 firewall bypass. IPv6 TURN and connectivity from another network remain separate acceptance items.

The process uses a separate PM2 home, preserving existing PM2 applications: `PM2_HOME=/root/cypher/browser-llm-lab/.runtime/relay-turn/pm2 pm2 list`. Its name is `cypher-header-turn`; start command is `PM2_HOME=/root/cypher/browser-llm-lab/.runtime/relay-turn/pm2 pm2 start /root/cypher/browser-llm-lab/.runtime/relay-turn/start.sh --name cypher-header-turn --interpreter none --max-memory-restart 96M --restart-delay 3000 --kill-timeout 5000`. The PM2 memory restart threshold is a soft safeguard, not a hard memory limit. Stop only this instance with the same PM2 home and `pm2 stop cypher-header-turn`. The scoped Web startup unit starts only the gateway and this dedicated TURN instance; it does not restore a global PM2 dump or restart existing applications. Coturn request logs are disabled to avoid retaining peer addresses or ephemeral authentication data. Operators should monitor bounded aggregate process/socket and transfer metrics without logging credentials.

The gateway accounts for its HTTP/signaling payload quota; the browser separately accounts for direct/TURN DataChannel payload in its 100 MiB per-ON budget. Coturn enforces allocation and rate caps, not a cumulative per-ON 100 MiB meter or session-token revocation. These controls do not measure full encrypted/retransmitted ISP bytes. Run `RELAY_TURN_TEST=1 node --test tests/relay-turn.test.mjs` only against this dedicated configured instance for actual authentication/quota/private-destination checks. The mesh browser harness separately forces relay candidates and verifies opaque RLPx chunks, their digests, independent browser receipts and native chain hashes. A local forced-TURN result does not establish restrictive NAT or different-network connectivity; report those as `NOT_RUN` until tested.

The automatic-discovery update and native endpoint signer have separate rollout evidence in `relay/evidence/discovery-update/`. Older deployment/capacity records remain historical; feature descriptions alone do not establish that a particular Web build is already deployed. For the browser fixture, set `PLAYWRIGHT_MODULE` and `CHROMIUM` to durable installed paths; the defaults under `/tmp` are environment conveniences, not runtime dependencies. See [discovery protocol](discovery-protocol.md) for the current home-gateway bootstrap boundary and reproduction requirements.
